# ITプロジェクトのリスク対応(Risk Response)

## 1. 概要

### A. 定義
> **リスク対応(Risk Response)** とは、プロジェクト目標を脅かす、あるいは逆に機会となり得る**不確実性(リスク)を特定・分析し、それに適した対応戦略を策定・実行**する管理活動である。PMBOKのリスク・マネジメント知識エリアの中核プロセスである。

リスクの定義で見落とされやすい点は、リスクが**否定的な脅威だけでなく肯定的な機会も含む**ということである。伝統的にリスク管理は「悪いことを防ぐこと」とだけ理解されがちだが、PMBOKは予想以上に物事がうまく進む可能性(機会)もまた管理対象とみなす。脅威は最小化し機会は最大化することが、リスク対応の完全な目標である。

### B. 必要性
ITプロジェクトは要求事項の変更、新技術の導入、厳しいスケジュールなどにより**不確実性がとりわけ高い**。こうした不確実性を放置すると、スケジュール遅延・予算超過・品質低下につながる。リスクを事前に特定し対応計画を準備しておけば、問題が実際に発生したときに慌てることなく準備された措置を実行できるため、プロジェクトの成功確率が高まる。

## 2. リスク対応計画の策定手順 (A)

```mermaid
flowchart LR
  A[リスクの特定] --> B[定性的分析<br/>発生確率・影響] --> C[定量的分析] --> D[対応計画の策定] --> E[対応の実行・コントロール]
  E -. 再評価 .-> A
  style D fill:#e8f0fe,stroke:#2f6fed,stroke-width:2px
```

手順の論理は、**「すべてのリスクを同じように扱うことはできないので、絞り込んで集中する」** というものである。まず特定段階でリスク一覧(Register)を幅広く作成する。続いて**定性的分析**で発生確率と影響度を組み合わせたP-I Matrixによって優先順位を付け、重要な少数に資源を集中させる。大きなリスクは**定量的分析**で金額・スケジュールへの影響を数値化するが、ここでEMV(期待金額価値)やモンテカルロ・シミュレーションが用いられる。この分析を土台にリスクごとの対応計画を立て、実行段階ではトリガーをモニタリングしながら残存リスク・二次リスクまで管理する。リスクはプロジェクトの進行中に変化し続けるため、この手順は**定期的に再評価**される。

| 段階 | 内容 |
|---|---|
| **特定** | リスク一覧(Register)の作成 |
| **定性的分析** | 発生確率・影響度の評価(P-I Matrix)、優先順位付け |
| **定量的分析** | 金額・スケジュールへの影響の定量化(EMV、モンテカルロ) |
| **対応計画** | リスクごとの戦略・担当者・予備費(Contingency)の指定 |
| **実行・コントロール** | トリガーのモニタリング、残存・二次リスクの管理 |

## 3. 脅威(否定的リスク)に対する対応戦略 (B)

脅威への対応戦略は、リスクの**大きさと性格に応じて**使い分ける。深刻で受け止めきれない脅威は原因そのものを取り除く**回避**で対応し(例:検証されていない技術を用いる範囲を丸ごと除外)、自組織でうまく扱えない脅威は保険・アウトソーシングによって第三者に**転嫁**する。大半の脅威は確率や影響を減らす**軽減**で扱い(例:プロトタイプで技術リスクを検証、冗長化で障害の影響を縮小)、発生しても受け止められる小さな脅威は予備費だけを確保して**受容**する。

| 戦略 | 内容 | 例 |
|---|---|---|
| **回避(Avoid)** | 脅威の原因を除去 | リスクの大きい範囲の削除 |
| **転嫁(Transfer)** | リスクを第三者へ移転 | 保険・アウトソーシング・契約 |
| **軽減(Mitigate)** | 発生確率・影響を低減 | プロトタイプ・冗長化 |
| **受容(Accept)** | 特別な措置をとらずに甘受 | 予備費の確保(小規模リスク) |

## 4. 機会(肯定的リスク)に対する対応戦略 (C)

機会への対応は、脅威の戦略と**対称構造**をなす。回避↔活用、転嫁↔共有、軽減↔強化が対になり、受容は共通である。確実につかみたい好機は必ず実現されるよう**活用**し(例:優秀な人材を優先投入して早期完了)、単独よりもパートナーと組むことで大きくなる機会は**共有**し(ジョイントベンチャー・パートナーシップ)、発生確率や利得を高められる機会には資源を追加投入して**強化**する。特段の措置をとらず、発生すれば利得だけを享受するのが**受容**である。

| 戦略 | 内容 | 例 |
|---|---|---|
| **活用(Exploit)** | 機会を確実に実現 | 優秀な人材の優先投入 |
| **共有(Share)** | 第三者と協力して実現 | パートナーシップ・ジョイントベンチャー |
| **強化(Enhance)** | 発生確率・影響を増大 | 資源の追加投入 |
| **受容(Accept)** | 積極的な措置なしに機会を活用 | 発生時に利得を享受 |

## 5. 考慮事項および示唆点
- **脅威・機会の双方を管理しつつエスカレーションを活用**: プロジェクトマネージャーの権限を超えるリスク(戦略・組織レベル)は上位管理層へ**エスカレーション**し、対応主体を明確にする。
- **予備費による財務的な備え**: 既知のリスクは**Contingency Reserve**、未知のリスクは**Management Reserve**として区分して確保する。前者はPMが、後者は上位管理層が統制する。
- **アジャイル環境での反復的な再評価**: 要求が頻繁に変わるITプロジェクトでは、スプリント単位でリスクを再評価し、変化に迅速に対応することが効果的である。
- **残存・二次リスクの管理**: 対応を実行した後に残る残存リスクと、対応が新たに引き起こす二次リスクまで追跡してこそ、管理の実効性が確保される。

---

> **一言まとめ**: リスク対応は*特定→定性/定量分析→対応計画→実行・コントロール*の手順で優先度の高いリスクに集中し、脅威は*回避・転嫁・軽減・受容*、機会は*活用・共有・強化・受容*の対称的な戦略で管理し、エスカレーション・予備費で補完する。

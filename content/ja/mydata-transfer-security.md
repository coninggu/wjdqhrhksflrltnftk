# マイデータ転送セキュリティ(マイデータ転送セキュリティ案内書、2023.09)

## 1. 概要

### A. 定義・背景
> マイデータ(本人信用情報管理業)において、**情報主体の要求に応じて個人(信用)情報を機関間で転送する際に生じるリスクを統制するための安全措置基準**をまとめた案内書であり、転送者・受信者の双方に保護責任者の指定・アクセス管理・管理的安全措置を求める。

マイデータの本質は、複数の機関に散在する自分の情報を、**情報主体の転送要求権**に基づいて一箇所に集めて活用することである。この過程で、銀行・カード会社・通信事業者などの情報提供者とマイデータ事業者との間で、大量の機微な個人情報が**APIを通じて常時やり取りされる**という点が中核的なリスクである。データが移動する瞬間こそが漏洩・偽変造・誤送信のリスク区間であるため、転送の全区間を安全に統制することがマイデータの信頼の前提となる。

### B. 必要性
マイデータの普及に伴い、転送される情報の量と参加機関の数が急増し、一つの機関のセキュリティ上の欠陥がエコシステム全体の信頼を崩しかねない構造となった。特に、資産・所得・信用といった**財産関連の機微情報**が対象であるため、漏洩時の被害が直接的で回復が難しい。そこで韓国の個人情報保護委員会は、信用情報法・個人情報保護法の安全措置義務をマイデータ転送の文脈に合わせて具体化した案内書を通じて、転送者と受信者が**同一水準の保護責任**を負うよう基準を統一した。

## 2. 転送対象の個人情報保護責任者(CPO)の指定

安全措置は、結局のところ「誰が責任を持って管理するのか」から出発する。技術的統制をいくら整えても、それを統括・点検する主体がいなければ、事故時の対応が迷走するからである。案内書は、転送業務を管掌する**個人情報保護責任者(CPO)**を明確に指定し、転送セキュリティポリシーの策定と履行点検、侵害事故対応を統括させる。このときCPOは実効的な権限と**独立性**を持ち、経営陣に直接報告できなければならない。現業部門に従属していると、利便性のためにセキュリティ統制を緩めようとする圧力に抵抗しにくいからである。

| 項目 | 内容 |
|---|---|
| **CPOの指定** | 転送業務を統括する保護責任者の指定・責任の明確化 |
| **役割** | 転送セキュリティポリシーの策定・履行点検、侵害事故対応の統括 |
| **独立性** | 実質的な権限・独立性の付与、経営陣への直接報告体制 |

## 3. 転送対象の個人情報処理システムのアクセス管理

```mermaid
flowchart LR
  A[アクセス権限の最小化] --> B[認証の強化]
  B --> C[アクセス記録の管理]
  C --> D[異常行為の検知]
```

アクセス管理の原理は、**「必要な人が、必要な分だけ、痕跡を残して」**と要約される。個人情報処理システムに対する権限を最小限に付与し、職務を分離する(開発者と運用者の分離など)理由は、一つのアカウントが奪取されてもアクセス可能な情報の範囲を狭めて被害を局所化するためである。加えて、パスワードのみの単一認証はなりすましに弱いため、**多要素認証(MFA)**によってアカウント盗用のリスクを下げ、すべての接続・処理行為を**アクセス記録として残し、改ざん防止措置**とともに保管する。アクセス記録は事後追跡の根拠であるだけでなく、深夜の大量照会のような**異常行為をリアルタイムで検知**する入力となり、事故を早期に遮断する。例えば、あるアカウントが普段の数百倍に及ぶ転送要求を送った場合に、自動遮断・通知が発動するよう設計する。

| 項目 | 内容 |
|---|---|
| **アクセス権限** | 最小権限・職務分離、権限付与・回収の定期的な見直し |
| **認証** | 多要素認証など安全な認証手段、アカウント・セッション管理 |
| **アクセス記録** | 接続・処理記録の保管および改ざん防止 |
| **統制・検知** | アクセス制御システム、異常行為のモニタリング・自動遮断 |

## 4. 個人情報の管理および災害・災難への備え

転送データの安全は、**移動中(in transit)と保存中(at rest)**の両方を守ってはじめて完成する。転送区間はTLSで、保存データは暗号化によって、中間者攻撃や記憶媒体の奪取時にも内容を保護する。さらに、データが伝達過程で改変されていないことを保証する**完全性検証**と、漏洩の試みを検知・遮断するDLP的な統制を設ける。一方、マイデータは多数の機関がリアルタイムで接続されたサービスであるため、**可用性そのものがセキュリティ要件**となる。特定機関のシステムが災害で停止すると転送チェーン全体が影響を受けるため、バックアップ・復旧体制(BCP/DRS)と冗長化によってサービスの継続性を確保し、侵害事故発生時の迅速な対応・届出手続きを事前に整備しておく。

| 項目 | 内容 |
|---|---|
| **暗号化** | 転送区間(TLS)・保存データの暗号化 |
| **完全性・漏洩防止** | 転送データの改ざん防止、漏洩の検知・遮断(DLP) |
| **災害・災難への備え** | バックアップ・復旧(BCP/DRS)、システム冗長化による継続性の確保 |
| **事故対応** | 侵害事故対応手順・届出体制の策定 |

## 5. 考慮事項および示唆(技術士の観点)
- **転送全区間の信頼の連鎖**:認証・暗号化・アクセス制御のいずれか一箇所が弱ければ全体が崩れるため、相互認証(mTLS)ベースのAPIセキュリティと組み合わせてエンドツーエンドの信頼を確保する。
- **標準APIとセキュリティの整合**:マイデータ標準API(機能適合性・セキュリティ適合性審査)と本案内書の安全措置を併せて満たさなければならず、アクセストークンの最小権限・短い有効期間の設計が実務上の鍵となる。
- **法・制度の遵守**:信用情報法・個人情報保護法の安全性確保措置基準と整合させ、定期点検・役職員教育によって管理的統制の実効性を維持する。
- **エコシステムの信頼こそが競争力**:参加機関全体が同一水準のセキュリティを守らなければならないため、脆弱な参加者を排除する認証・監督体制がマイデータ普及の前提となる。

---

> **一言まとめ**: マイデータ転送セキュリティ案内書は、*保護責任者(CPO)の指定、処理システムのアクセス管理(最小権限・多要素認証・アクセス記録)、個人情報の管理・災害対策(暗号化・完全性・バックアップ・事故対応)*を通じて、機関間で転送される機微情報の信頼の連鎖を確保するよう求めている。

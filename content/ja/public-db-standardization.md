# 公共データベース標準化管理(予防的品質管理、2023.04)

## 1. 概要

### A. 定義および背景
> 韓国の行政安全部が**高品質な公共データの提供・開放・活用**のために『公共データベース標準化管理マニュアル』(2023.04)で提示した、システムの**構築段階からエラーを予防**する事前(予防的)品質管理の基準。

公共データは国民向けサービス・政策決定・民間活用(マイデータ・AI学習)の源泉であるため、一つのデータのエラーが複数の機関・サービスへと**拡散・増幅**される。従来の品質管理が、データがすでに蓄積された後にエラーを探して修正する**事後(是正的)方式**に偏っていたとすれば、このマニュアルは標準を設計・構築の時点で組み込み、**エラーが発生する前に遮断**する方向へと重心を移した点が核心である。

### B. 必要性
事後のデータクレンジングは、すでに誤って入力・連携されたデータを追跡して元に戻さなければならないためコストが大きく、すでに配布・連携されたデータのエラーは回収も難しい。例えば標準用語なしに部署ごとに「住民登録番号/住民番号/住民登録No」をばらばらに使っていると、その後の連携・統合のたびにマッピング・クレンジング作業が繰り返される。標準単語・ドメイン・用語を**分析段階であらかじめ確定**すれば、こうした反復コストと整合性エラーを根本から遮断できるため、「構築段階から品質を組み込む」予防的アプローチが求められる。

## 2. システム構築段階別の予防的品質管理活動

```mermaid
flowchart LR
  A[分析] --> D[設計] --> I[実装] --> T[試験・移行] --> O[運用]
```

品質管理活動をSDLCの全段階に配置する理由は、**エラーの発見が遅れるほど修正コストが指数関数的に大きくなるから**である。要求・標準を分析段階で押さえられなければ、設計・実装を経る中でエラーがコードとデータに固定化し、運用段階ではクレンジング・再構築という高い代償を払うことになる。そのため各段階に次のような防御線を設ける。

| 段階 | 予防的品質管理活動 | 目的 |
|---|---|---|
| **分析** | データ要求・標準の定義、標準単語・標準ドメイン辞書の策定 | 標準の不在による命名・意味の混乱を予防 |
| **設計** | 標準に準拠したデータモデリング、整合性・制約ルールの設計 | モデルの整合性・参照整合性を事前に確保 |
| **実装** | 標準を反映したDB構築、制約条件(NOT NULL・FK・CHECK)の適用 | 誤った値の入力そのものを遮断 |
| **試験・移行** | 品質の診断・検証、データクレンジング・移行の整合性検証 | 移行過程での欠落・歪曲を防止 |
| **運用** | 継続的な品質モニタリング・改善、定期診断 | 運用中の品質低下(ドリフト)を管理 |

特に**実装段階の制約条件**は、予防的統制の代表例である。カラムにドメイン・CHECK制約をかけておけば有効範囲を外れた値はそもそも保存されないため、事後に異常値を探して削除する作業自体が不要になる。

## 3. 予防的品質管理の4つの診断領域・9つの診断項目

診断は、「標準が正しく定義されているか → その標準がモデルに反映されているか → 実際の値と構造が標準・ルールを守っているか」という**上流から下流への流れ**に沿って、4つの領域で構成される。上流(標準化)が崩れれば、下流(値・構造)の診断がいかに緻密であっても根本的なエラーは防げないため、領域間には依存関係がある。

| 診断領域 | 代表的な診断項目 | 何を保証するか |
|---|---|---|
| **標準化** | 標準単語、標準ドメイン、標準用語 | 用語・意味の一貫性 |
| **モデル品質** | データモデルの整合性、命名規則の遵守 | 標準のモデルへの反映・構造の一貫性 |
| **値の品質** | 必須値(NOT NULL)・有効値(ドメイン)の遵守 | 実際に格納された値の正確性・完全性 |
| **構造・整合性** | 参照整合性、コードの整合性 | 関係・コード値の整合性 |

> 上記4領域の下に、計**9つの診断項目**(標準単語・標準ドメイン・標準用語、データモデルの整合性・命名規則、必須値・有効値、参照整合性・コードの整合性など)によって事前診断を実施する。

例えばコードの整合性診断は、「性別コードのカラムに標準コードセット(1/2/9)以外の値がないか」を確認するものであるが、これを標準用語・標準ドメインの定義と結び付けて点検することで、値・構造・標準が互いに食い違わないよう相互検証する。

## 4. 期待効果

| 効果 | 内容 | 根拠 |
|---|---|---|
| **品質の向上** | エラー・重複の事前除去、整合性の確保 | 入力時点での遮断によりエラーの流入を最小化 |
| **コスト削減** | 事後のクレンジング・手戻りコストの減少 | 修正が遅れるほど増大する修正コストを回避 |
| **活用性の向上** | 開放・連携データの信頼性・再利用性↑ | 標準化により機関間の連携・統合が容易 |

## 5. 考慮事項および示唆
- **データ標準化・ガバナンス体制との連携**: マニュアルの標準単語・ドメイン辞書は、全社的なデータガバナンス(標準管理組織・プロセス)の上で維持・更新されてこそ実効性がある。標準を作っても管理主体がいなければ、時間の経過とともに再び乱れてしまう。
- **開放・マイデータ・AI学習データの品質基盤**: 公共データが民間サービスやAI学習に再利用されるにつれ、源泉データの品質がそのまま派生サービスの品質を左右する。「ゴミを入れればゴミが出てくる(GIGO)」という問題を上流で防ぐという点で、戦略的な価値が大きい。
- **自動化と組織**: 診断項目を自動診断ツールで定期的に実行し、品質管理の専任組織・役割を設けて、予防-診断-改善の循環を制度化する。
- **トレードオフ**: 初期の標準策定・モデリングにはより多くの時間と人員を要するが、これは事後のクレンジング・エラー拡散のコストに比べればはるかに安価な先行投資である。

---

> **一言まとめ**: 公共DB標準化管理マニュアルは、*構築段階(分析~運用)ごとに予防的品質管理活動*を配置し、*標準化・モデル・値・構造整合性の4つの診断領域と9つの診断項目*で事前診断することで、エラーが発生・拡散する前に遮断し、開放・連携・AI学習データの品質基盤を確保する。

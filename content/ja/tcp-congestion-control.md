# TCP輻輳制御（Congestion Control）

## 1. 概要

### A. 定義
> ネットワークに**輻輳（パケットの過負荷）が発生したとき、送信速度を調整して輻輳を緩和**するTCPのメカニズムである。受信側の処理速度に合わせるフロー制御（Flow Control）とは異なり、ネットワーク全体の負荷を扱う。

輻輳制御が必要な根本的理由は、「**輻輳崩壊（Congestion Collapse）の防止**」である。複数の送信者がネットワークの状態を無視してデータを無秩序に送り出すと、中間ルータのキューがあふれてパケットが破棄される。すると送信者は失われたパケットを再送し、この再送がさらに輻輳を拡大させる悪循環が生じ、最終的にネットワークのスループットがゼロに収束する崩壊が起こる。TCPはこれを防ぐために巧妙な仮定を置く。無線エラーがまれな有線網では**パケット損失をそのまま輻輳のシグナルと解釈**し、損失が検知されると自ら送信量を減らす。すなわち個々の端点（TCP）が協調的に速度を調整し、ネットワークという共有資源を保護するのである。

### B. 必要性
インターネットは無数の端点が共有する資源であるため、各自が自分の速度だけを押し通せば全体が崩壊する。輻輳制御は、端点同士が自律的に協力してネットワークを安定的に維持するための中核的な仕組みである。

## 2. 輻輳制御メカニズムの構成要素

```mermaid

  A[スロースタート] --> B[輻輳回避] --> C[高速再送] --> D[高速回復]
  style A fill:#e8f0fe,stroke:#2f6fed,stroke-width:2px
```

輻輳制御は4つの要素で動作する。**スロースタート**は、接続初期に輻輳ウィンドウ（cwnd）を1から指数的に（1→2→4→8）急速に拡大して利用可能な帯域を探索するが、閾値（ssthresh）に到達すると停止する。**輻輳回避**は、閾値以降にウィンドウを1ずつ線形に増加させ、慎重に帯域を広げる。**高速再送**は、重複ACKが3回届くとタイムアウトを待たずに即座に損失パケットを再送する。**高速回復**は、再送後にスロースタートへ戻らず輻輳回避状態に復帰し、急激な速度低下を防ぐ。

| 構成要素 | 内容 |
|---|---|
| **スロースタート** | cwndを指数的に増加（1→2→4…）、ssthreshまで |
| **輻輳回避** | 閾値以降は線形（1ずつ）に増加 |
| **高速再送** | 重複ACK 3回で即時再送 |
| **高速回復** | 再送後に輻輳回避へ復帰 |

## 3. 輻輳状況の検知

TCPは2つのシグナルで輻輳を検知する。**タイムアウト（RTO）**は応答が長時間ない深刻な損失であり、強い輻輳を意味するためウィンドウを大きく縮小する（1に初期化）。**重複ACK 3回**は一部のパケットのみが失われた軽微な状況であり、高速再送・高速回復で対応する。近年では、損失が発生する前にルータがビットで輻輳を事前に通知する**ECN（明示的輻輳通知）**も活用されている。

| シグナル | 意味 |
|---|---|
| **タイムアウト（RTO）** | 深刻な損失 → cwndの初期化 |
| **重複ACK 3回** | 軽微な損失 → 高速再送・高速回復 |
| **ECN** | ルータが損失前に輻輳を通知 |

## 4. 輻輳状況の制御と輻輳ウィンドウ（cwnd）

中核となる変数である**輻輳ウィンドウ（cwnd）**は、まだ確認応答を受けていない状態で送信できるデータ量、すなわち送信速度を表す。実際の送信量は、輻輳ウィンドウと受信ウィンドウ（rwnd）のうち**小さい方の値**で決定される（両方を満たす必要があるため）。輻輳が検知されると、閾値（ssthresh）を現在のcwndの半分に下げてcwndを縮小し、その後再び徐々に増やしていく。この「増加し、損失が起きれば減少する」を繰り返すのこぎり歯（sawtooth）状の形がTCP輻輳制御の特徴である。

| アルゴリズム | 特徴 |
|---|---|
| **Tahoe** | 損失時にスロースタートへ復帰 |
| **Reno** | 高速回復を導入 |
| **CUBIC** | 広帯域・高遅延に最適（Linuxのデフォルト） |
| **BBR** | 帯域幅・RTTの推定に基づく（Google） |

## 5. 考慮事項および示唆点

1. **損失ベースからモデルベースへと進化**している。従来のReno・CUBICは損失を輻輳シグナルとするが、GoogleのBBRは帯域幅と遅延を直接推定し、損失なしでも最適な速度を見つける。
2. **ネットワーク特性に合ったアルゴリズムの選択**が重要である。データセンターの低遅延・広帯域環境と、無線・衛星の高損失環境とでは最適なアルゴリズムが異なるため、環境に合わせて調整する。
3. **能動的な輻輳シグナル（ECN）により損失前に対応**する方向へ発展している。パケットを破棄して知らせる代わりに、事前に通知を受けて先制的に調整すれば、再送を減らし遅延を低減できる。

---

> **一言まとめ**: TCP輻輳制御は*スロースタート・輻輳回避・高速再送・高速回復*によって輻輳ウィンドウ（cwnd）をのこぎり歯状に調整し、タイムアウト・重複ACKで輻輳を検知して送信量を減らすことで輻輳崩壊を防止し、BBR・ECNへと進化している。
